# 1.2.3 — instant Ctrl+H restore

Glance now sets `DWMWA_TRANSITIONS_FORCEDISABLED` on its own dashboard and overlay HWNDs. Windows' show/hide transition is disabled for those windows only. The existing synchronous shortcut dispatch, opacity, focus, click-through, bounds and provider UI remain unchanged.

Electron's `thickFrame: false` also removes animations, but disables native edge resizing. This patch keeps the existing frame behavior and uses the per-window DWM policy instead. See [Microsoft's documented attribute](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute).

The policy is configured once per window by a hidden PowerShell interop helper, asynchronously while the window/page loads. No process is launched and no promise is awaited by Ctrl+H. The helper checks that the window belongs to the current process, checks the native API's result, has a five-second timeout, and reports failure without disabling window controls. Existing Windows PowerShell is used; no dependency or system-wide setting was added. If PowerShell/native configuration is blocked, or the user toggles immediately before setup finishes, native transitions may still occur.

The integration test checks Windows accepts the policy on both windows and performs five Ctrl+H hide/show cycles, checking visibility immediately after the shortcut, along with unchanged opacity, position, size, and resizability. The attribute is documented for setting; a readback probe was not supported on the test system and was removed. No visual frame-by-frame animation measurement is claimed.
